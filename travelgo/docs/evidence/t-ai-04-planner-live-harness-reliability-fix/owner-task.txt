## 2. H02 — Sửa fidelity assertion

Nguyên nhân:

Harness so sánh JavaScript object có optional property `placeId: undefined` với JSON response đã serialize, trong đó property đó không còn.

Yêu cầu:

1. Đọc production public response contract.
2. Xác định chính xác representation mà browser/API phải nhận.
3. So sánh public JSON projection với independent JSON oracle cùng representation.
4. Chỉ normalize hai volatile fields đã được phê duyệt:
   - `itinerary.id`
   - `itinerary.createdAt`
5. Không bỏ qua price, dates, place IDs, ETA, warnings, selectedPlaceIds hoặc bất kỳ business field nào.
6. Không tự biến mismatch thật thành PASS.
7. Không thay original expected.

Test cả positive và negative:

- Saved L01/L02/L03 public JSON khớp oracle.
- Sai total phải FAIL.
- Sai place ID phải FAIL.
- Sai ngày phải FAIL.
- Sai transport/ETA phải FAIL.
- Thiếu hoặc thừa required field phải FAIL.
- Source/provenance sai phải FAIL.

Không sửa Planner hoặc serializer production.

## 4. H04 — Global fail-fast

Đây là yêu cầu quan trọng nhất.

Sửa orchestration để mọi FAIL thuộc các lớp sau đều kích hoạt global stop:

- Manifest/hash mismatch.
- Request/response assertion.
- Fidelity assertion.
- Browser UI assertion.
- Session/revision mismatch.
- Auth/ownership error.
- Unauthorized tool execution.
- Native POST cap.
- Quota/TTL.
- Unexpected DB mutation.
- Runtime/security guard.
- Unexpected error/timeout.

Khi gặp FAIL:

1. Ghi failure evidence.
2. Đánh dấu case hiện tại FAIL.
3. Chặn mọi case kế tiếp.
4. Không dispatch HTTP Agent request mới.
5. Không gửi Ollama POST.
6. Không retry.
7. Chạy `finally`/cleanup an toàn theo contract nếu có tài nguyên cần giải phóng.
8. Ghi các case chưa chạy là NOT RUN.
9. Trả nonzero exit code.

Không được catch assertion error rồi chỉ log và tiếp tục.

Không dùng skip/continue để che lỗi.

Cleanup không được bị bỏ qua vì assertion thất bại, nhưng cũng không được vượt guard cleanup.

## 5. INDEPENDENT OFFLINE ACCEPTANCE

Tạo một harness test suite mới, độc lập với implementation đã sửa.

Bắt buộc kiểm:

### Fidelity

- Saved public JSON L01–L03.
- Wrong cost/ID/date/transport.
- Missing required fields.
- Unexpected result source.

### Unicode

- UTF-8 source parsing.
- Exact text `Xe máy`, `Ô tô`, `₫`.
- Corrupted literal rejection.
- Desktop/mobile mocked DOM.
- Manual confirmation locator.

### Global stop

Inject failures vào:

- Fidelity tại L01.
- UI tại L01.
- Raw expected mismatch.
- Manifest guard.
- Session revision.
- Tool safety.
- Simulated provider timeout.
- Cleanup precondition.

Với mỗi injected FAIL, assert:

- Global stop activated.
- Later cases NOT RUN.
- No later inference dispatch.
- No retry.
- Proper cleanup/finally invocation.
- Nonzero process exit.
- Original failure preserved.

Đặc biệt phải chứng minh tình huống run2:

**L01 fidelity FAIL → L02/L03/L04 tuyệt đối không chạy.**

Đồng thời phải chứng minh success path có thể chạy tiếp các case khi tất cả guards PASS.
