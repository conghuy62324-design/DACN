# PHASE A — HARNESS FIX OFFLINE

## 2. Sửa H01

Lỗi đã xác nhận:

Frontend gửi URL:

`/api/agent/verified-history/<server-created-id>/reset`

Nhưng test harness không thay placeholder `$desktop.id` khi placeholder nằm giữa một URL đầy đủ.

Nhiệm vụ:

1. Đọc đúng implementation harness hiện tại.
2. Review proposed patch.
3. Sửa cơ chế bind placeholder ở harness.
4. Hỗ trợ placeholder nằm trong full URL/path.
5. Không thay nhầm các chuỗi không phải placeholder.
6. Không thay session ID bằng giá trị client tự tạo.
7. Không bỏ exact path/body/hash guards.
8. Không sửa production Agent routes.

Chỉ sửa file harness/test mới được phép.

## 3. Offline acceptance

Tạo independent tests cho:

- Placeholder là toàn bộ value.
- Placeholder nằm trong URL path.
- Reset endpoint.
- Revoke endpoint.
- Start/continue request.
- Server-created UUID.
- Fresh requestId.
- Unresolved placeholder bị reject.
- Sai endpoint vẫn bị guard chặn.
- Sai method/body vẫn bị guard chặn.
- URL encoding đúng.
- Không thay các chuỗi trùng một phần nhưng không phải token.

Thực hiện dry integration:

Frontend thật → local test HTTP router → production reset/revoke G2 code.

Dùng fake provider/consent và in-memory session để tránh Ollama/PostgreSQL.

Kiểm reset thật trả đúng metadata/revision, revoke xóa session đúng owner.

Nếu offline tests FAIL, không bước sang PHASE B.

## 4. Phase A exit gate

Bắt buộc:

- Harness patch PASS.
- Dry integration PASS.
- Không bỏ guard.
- Không production changes.
- 0 Ollama POST.
- 0 PostgreSQL access trong offline harness.
- Source/evidence baseline nguyên vẹn.

Nếu đạt, ghi `PHASE_A_PASS`.
