# TASK T-AI-04-G2-BROWSER-AND-REAL-TOOL-E2E

Vai trò: Senior Full-stack Engineer, AI Engineer, Database QA Engineer, Security Engineer và E2E Test Lead của TravelGo.

## MỤC TIÊU

Kiểm thử end-to-end AI Agent TravelGo bằng:

- Frontend React thật.
- Backend Agent API thật.
- G2 Verified History local/demo.
- Qwen3 chạy thật trên Ollama local.
- Execution provenance gate thật.
- Catalog/Planner service thật.
- PostgreSQL test database.
- Browser desktop/mobile.

Phân biệt rõ chất lượng raw NLU, session/history, safety, tool fidelity và UI.

Đây là **LIVE E2E VALIDATION**, không phải task FIX.

### Phạm vi quyền được cấp khi chủ dự án gửi task

- Tối đa **8 native Ollama POST** tổng cộng.
- Trong đó tối đa 1 conditional operator load-only và 7 inference.
- 0 retry hoặc hidden warm-up.
- Chỉ được dùng database `travelgo_ai_m0_test` sau khi xác minh chính xác identity và safety guards.
- Mặc định **READ-ONLY với PostgreSQL**.
- Không tự tạo seed/fixture, sửa, xóa hoặc truncate dữ liệu.
- Không sửa production source, benchmark hoặc historical evidence.
- Không commit/push/deploy.

Nếu môi trường hoặc guard không đạt, dừng phần LIVE tương ứng, báo BLOCKED; không vượt quyền để đạt PASS.

## 2. Preflight và manifest

Trước khi chạy inference:

1. Kiểm toàn bộ source và các hash baseline.
2. Xác nhận frontend/backend build.
3. Kiểm G2 API contract và privacy notice.
4. Kiểm môi trường local và test DB.
5. Xác nhận mô hình Ollama.
6. Kiểm principal/AgentLimits và rolling ledger.
7. Kiểm RAM/VRAM, readiness và provider concurrency.
8. Xác định các tình huống có thể chạy thật với catalog hiện có.

Khóa manifest trước mọi native POST.

Manifest phải ghi:

- Exact input.
- Viewport.
- Authenticated principal.
- Session action/revision.
- Expected raw NLU.
- Expected tool/arguments.
- Expected service result/provenance.
- Expected UI behavior.
- Native POST budget.
- Stop conditions.
- Input/request hashes.

Với request chứa session ID do server tạo, khóa body template và quy tắc thay ID trước khi chạy; kiểm exact final body/hash tại dispatch.

Không thay expected sau khi đã thấy model output.

## 3. Database guard

Chỉ dùng:

`travelgo_ai_m0_test`

Trước bất kỳ truy vấn dữ liệu:

- Xác nhận host, port, database name và role.
- Xác nhận database không phải production hoặc `travelgo_dev`.
- Đối chiếu schema/migration checksum thực tế với baseline được duyệt.
- Chụp fingerprint/sentinel phù hợp cho các bảng liên quan.
- Kiểm quyền READ-ONLY, không mở đường ghi dữ liệu.
- Không reset/migrate/seed/truncate.
- Không sửa dữ liệu Trip/Booking hoặc tài khoản thật.

Ưu tiên dùng dữ liệu catalog có sẵn trong test DB.

Nếu catalog không có dữ liệu phù hợp, ghi `BLOCKED_DATA_READINESS` cho case liên quan. Không tự thêm dữ liệu để lấy PASS.

Nếu phát hiện cần tạo fixture hoặc thực hiện mutation để có bài test hợp lệ, dừng nhánh đó và đề xuất approval riêng.

Cuối task kiểm lại fingerprint/sentinel và xác nhận không phát sinh database writes.

Không tự nhận fingerprint PASS nếu DB chưa được truy cập hoặc chưa có snapshot so sánh thực tế.

## 6. Test cases LIVE

Lựa chọn tối đa 7 lượt inference từ các case dưới đây, theo dữ liệu Catalog/Planner đã xác minh.

### E01 — Search real Catalog

Người dùng yêu cầu tìm địa điểm du lịch phù hợp.

Kiểm:

- Model raw search_places.
- Required args đúng.
- Gate ALLOW.
- Catalog query thật.
- UI hiển thị đúng kết quả service.
- Không xuất hiện địa điểm không có trong actual service response.
- 0 mutation.

### E02 — G2 incomplete → complete plan

Người dùng bắt đầu lập lịch trình với một số trường chưa đầy đủ.

Các lượt thiếu thông tin:

- Backend hỏi đúng required fields.
- Không inference.
- Không tool.

Sau khi cung cấp đủ:

- Model raw plan_trip đúng.
- Gate kiểm merged verified proof.
- Planner thực thi đúng một lần.
- UI trả lịch trình từ real service result.
- Kiểm ngày, đêm, số người, phương tiện và chi phí.

Không tạo itinerary giả.

### E03 — Budget correction

Trong cùng owned G2 session, người dùng đổi ngân sách.

Kiểm:

- New budget verified.
- Các trường khác giữ đúng.
- Raw model và actual arguments.
- Planner không dùng ngân sách cũ nếu gate cho phép execute.
- UI hiển thị kết quả tương ứng với response thực.

### E04 — Natural transportation correction

Người dùng đổi phương tiện bằng tiếng Việt tự nhiên.

Kiểm:

- Current proof.
- Verified transportation.
- Raw decision.
- Safety.
- UI behavior.

Nếu model lại clarify transportation dù đã SET:

- Chấm RAW NLU FAIL.
- Safety PASS nếu không có unauthorized execution.
- Giữ nguyên state.
- Không tự chuyển clarify thành tool.

Không sửa input hoặc retry để lấy PASS.

### E05 — Manual confirmation

Người dùng chủ động bấm lựa chọn phương tiện trên UI.

Frontend gửi supported labeled message:

`Phương tiện: motorbike`

hoặc

`Phương tiện: car`

Kiểm new requestId, latest revision, normal quota, raw model và execution gate.

Không auto-resend.

Nếu AI vẫn hỏi lại, ghi FAIL tương ứng và kiểm người dùng có thể reset/end/manual edit.

### E06 — Destination/date correction

Kiểm một trường hợp correction hợp lệ khác với E03/E04.

Kiểm original source proof, raw, exact arguments, Catalog/Planner result và UI.

### E07 — Mobile LIVE smoke

Thực hiện ít nhất một luồng search hoặc plan thực trên mobile giả lập.

Không chỉ chạy mocked browser tests rồi nhận là mobile LIVE.

Kiểm viewport, form, request, model decision, tool invocation và render result.

**Phân bổ tối đa 7 inference trên desktop/mobile phải khóa trước khi chạy.**

Các case không được cấp inference hoặc không đủ điều kiện dữ liệu phải ghi NOT RUN; không phát sinh POST vượt budget để đủ tên case.

## 7. Deterministic lifecycle tests

Không gọi model nếu request không cần inference.

Kiểm:

- G2 privacy notice/acknowledgement.
- Start/continue với server-created ID.
- Exact revision/fresh UUID.
- Session expiry/unavailable.
- Reset.
- Revoke.
- Logout/account switch.
- Không hiển thị dữ liệu user cũ.
- Không stale response overwrite.
- Không client history cấp proof.
- G1 không nhận G2 transcript làm authenticated state.

Với logout, kiểm best-effort revoke; không nhận là JWT/global revocation.

Nếu phát hiện backend privacy notice cũ chưa phản ánh đúng hành vi frontend, ghi observation và proposed wording/version change riêng.

Không tự sửa privacy contract trong task E2E.

## 8. Chấm điểm độc lập

### A. Raw NLU

- Native raw trước server fallback.
- Expected kind/tool/arguments.
- Semantic PASS/FAIL.
- Schema validity.
- Timeout/no raw: semantic NOT EVALUATED, reliability failure riêng.

### B. Verified History

- Session ownership.
- Revision.
- Exact verified slots.
- Correction precedence.
- Unset/conflict behavior.
- No client history authority.

### C. Execution Safety

- Gate ALLOW/NEEDS_INPUT/REJECT.
- Old arguments blocked.
- No unauthorized tool.
- One read tool maximum.
- No mutation.

### D. Tool Fidelity

- Actual Catalog/Planner call.
- Arguments và output provenance.
- Direct service comparison.
- Dates, totals, budget warnings và data readiness.
- Real DB result nếu guard được phê duyệt và truy cập thành công.

Không tính fake executor marker là fidelity PASS.

### E. UI

- Browser request/response.
- Rendered values.
- Missing-field behavior.
- Confirmation controls.
- Error/retry/reset.
- Responsive desktop/mobile.

### F. Runtime

- Total native POST.
- Load-only vs inference.
- Timeout/abort.
- Model residency.
- Latency/tokens/cache.
- RAM/VRAM.
- GPU watchdog warnings.

Không cộng kết quả safety/UX tốt vào raw NLU.

## 10. Stop conditions

Dừng LIVE khi:

- Native POST cap đạt 8.
- Quota không đủ.
- Provider/model digest mismatch.
- Test database identity/guard không đạt.
- Có database write không được phép.
- Có unauthorized execution.
- Có authentication/session leakage.
- Request/session integrity bị sai.
- Có unexpected production source drift.
- Có lỗi runtime khiến không thể tiếp tục theo manifest.

Không tự sửa production hoặc rerun failed inference.

Nếu không thể kiểm phần real DB/tool, vẫn tổng kết các phần đã xác minh, ghi blocker chính xác; không giả full E2E PASS.
