## 2. PHASE A — STRICT IP NORMALIZATION

Thiết kế một bộ parser/canonicalizer có kiểm soát.

Không dùng giải pháp đơn giản như:

`address.split('/')[0]`

Bắt buộc phân biệt:

- IPv4 host address.
- IPv4 host `/32`.
- IPv6 host address.
- IPv6 host `/128`.
- Network prefix không phải host.
- Malformed address.
- Unsupported address family.

Ví dụ:

| Input | Expected |
|---|---|
| `172.18.0.3` | IPv4 host hợp lệ |
| `172.18.0.3/32` | Cùng host 172.18.0.3 |
| `172.18.0.3/24` | REJECT cho host identity |
| `172.18.0.0/24` | REJECT |
| `172.18.0.1/32` | IPv4 host hợp lệ, khác 172.18.0.3 |
| `::1` | IPv6 host hợp lệ |
| `::1/128` | Cùng host ::1 |
| `::1/64` | REJECT cho host identity |
| Malformed CIDR | REJECT |
| Wrong address family | REJECT |

So sánh bằng canonical address representation hoặc validated address bytes.

Không so sánh IPv4 với IPv6 chỉ dựa trên text.

IPv4-mapped IPv6, zone IDs, ambiguous encodings và các định dạng ngoài contract phải bị từ chối trừ khi được định nghĩa và kiểm chứng riêng.
