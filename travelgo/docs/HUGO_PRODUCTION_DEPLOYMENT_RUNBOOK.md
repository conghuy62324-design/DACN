## 2. Nghiệm thu stack và namespace

1. Sau phê duyệt, khởi động stack **staging** bằng cùng project/config và giữ worker profile chưa dùng. Khởi tạo DB tách bằng migrator có phạm vi. Kiểm migration 01–20 theo order và hashes; `node dist/scripts/migrate.js` mặc định chỉ lập kế hoạch. Chỉ chạy apply có duyệt theo đúng target và role. Runtime thường không được quyền schema change. Xác nhận health PostgreSQL, API `/api/health` từ trong container và SPA direct route.
2. API chia network namespace của Ollama. Ollama chỉ bind `127.0.0.1:11434`. API bind `0.0.0.0:5000` trong namespace do `TRAVELGO_PRIVATE_PROXY_ENABLED=true`. Gateway dùng `ollama:5000`, DNS resolver nội bộ xử lý đổi địa chỉ, frontend `frontend:8080`. Kiểm hai cổng này không collision, không publish, và client trong app network không vào được Ollama qua địa chỉ IP/service. Chỉ xác nhận endpoint private từ chính namespace API. Nginx ẩn `/api/health` ra ngoài.
3. Kiểm riêng các tình huống Ollama crash tự restart, Compose restart và recreate có đổi namespace. `depends_on.restart: true` chỉ hỗ trợ thao tác Compose, do đó sau recreate phải xác minh API vẫn cùng namespace mới, health/HTTP và readiness; nếu mất kết nối, đưa instance khỏi traffic và recreate API cùng Ollama theo scope staging. Không mở allowlist Ollama để thử lỗi. Kiểm DNS của gateway sau thay đổi container/IP. Kiểm lỗi DB khiến API health chuyển lỗi và hồi phục đúng.
4. Patch worker và DB prune nghiệm thu độc lập theo profile. Khi được phép, dùng DB exact, `REVIEW_PRODUCTION_DATABASE`, role `review_worker` không BYPASSRLS, chỉ đọc `review_ai_inputs` và `review_ai_targets` đã thu hẹp, các cột/đường ghi queue cần thiết. Xác minh browser invalidation trước profile thường trực. `REVIEW_WORKER_POLL_MS=60000`, `REVIEW_RECONCILE_TIME=03:00` theo Asia/Ho_Chi_Minh, batch 2 jobs; statement timeout 8 giây, shutdown grace 65 giây. Chỉ bật prune sau khi test quyền DELETE và scope, với limit mặc định 100 và tối đa 500 event COMPLETED đã xử lý hơn 90 ngày theo job revision. Kiểm sau restart, hai worker tranh job, hết lease, hết retry, heartbeat stale, terminal events và backlog. Chụp số tuổi event/cursor và số dòng bị tác động, giữ review gốc. ## 4. Backup và restore

**Lịch đề xuất để owner chốt với chính sách lưu giữ** là backup hằng ngày, giữ 7 bản ngày và 4 bản tuần, mã hóa và lưu off-server dưới quyền truy cập riêng. RPO ≤24 giờ và RTO ≤4 giờ là mục tiêu rehearsal đề xuất. Tránh đưa dump, secrets, raw review, chat hoặc dữ liệu khách vào Git/artifact công khai.

1. Chọn cửa sổ quiesce nếu cần nhất quán DB/media. Tạm ngưng ghi cần thiết, ghi UTC/ICT, source revision, schema migration manifest, extensions/server version và DB identity. Dùng backup role riêng đủ để lấy snapshot logic nhất quán, không dùng application role hoặc đưa mật khẩu vào command line. `pg_dump -Fc --no-owner --no-privileges --file="$BACKUP_DIR/db.dump" "$APPROVED_BACKUP_DSN"` từ client đúng major. Khôi phục role/grants từ permission manifest đã review. Nếu backup metadata role, tách và mã hóa riêng, tránh sao password hashes nếu không cần.
2. Snapshot volume media tại cùng mốc ổn định, lưu quyền/owner cần thiết theo service. Backup config ngoài Git bằng kho riêng gồm image digests, file version, DB role/grant policy, env schema, proxy, DNS/TLS renewal và model tag/digest, không nhúng secrets vào manifest. Nếu model cần phục hồi offline, sao artifact model đã được phép và hashes. Lập danh sách SHA-256 của dump, media và config bundle, kiểm ngay sau tạo và sau khi upload. Dùng off-server encryption/immutability theo chính sách owner.
3. Rehearsal dùng DB/container/network/volume **mới** có tên, port, sentinel và operator được duyệt; so chứng cứ identity trước kết nối. Kiểm sha256 và `pg_restore --list`. Phục hồi preconditions PostGIS/role, rồi `pg_restore --exit-on-error --no-owner --no-privileges --dbname="$NEW_RESTORE_DSN" "$BACKUP_DIR/db.dump"` vào target trống. Khôi phục media vào volume mới, kiểm quyền service đọc và ghi đúng scope. Cấu hình DNS/TLS rehearsal riêng và secrets phù hợp môi trường.
4. Verify schema/checksums, bảng/row counts hoặc fingerprints cần thiết, PostGIS, RBAC/consent, login/quote chính, media link, Agent cùng authoritative data và worker OFF lúc đầu. Đo thời gian, ngày snapshot, dữ liệu có thể mất, audit scope, quyền sau phục hồi và rollback. Không `DROP` DB đang có hay ghi đè volume nguồn. Chỉ bật lại job có gate đạt.
5. Khi migration lỗi, dừng task/ghi, lưu log đã lược bí mật và xác định transaction đã commit. Additive không tương thích phải hạ cờ, chạy app revision tương thích hoặc giữ readonly. Nếu phải khôi phục, chuyển sang target mới đã verify bằng cutover có duyệt. Chặn writer cũ trước khi đổi DSN để tránh split-brain. Ghi cutover và chọn cách xử lý phần ghi giữa hai snapshot. Giữ DB gốc phục vụ đối chiếu và bảo toàn dữ liệu.

- Monitors nội bộ gồm HTTP 5xx/latency, DB connectivity/pool/disk và tuổi backup dựa trên RPO, GPU readiness/VRAM/timeout/fallback, worker heartbeat/lease/FAILED/tuổi queue/prune, media errors và cert expiry. Verify health/revision sau khi quay image trước phù hợp checksum/schema, chạy lại HTTP, thử đăng nhập trên target có duyệt.
